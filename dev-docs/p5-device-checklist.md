## 旧包与签名限制

仓库根目录已有 canting_v0.1.0-beta.apk，但文件名不是实际版本：包内 versionName=1.0.0、versionCode=1、applicationId=com.canting.canting。它使用 Android Debug 证书。候选包需要重新核对实际证书、ABI及版本码，不只看名称。只有静态相容性不能宣称升级已通过。

正式签名由 Owner 管理，当前没有可交付的正式签名授权材料。推荐先用同签名候选包验证旧 beta 升级。新的正式密钥与旧 debug 签名不相容时，不能无损覆盖；应先提供导出/导入迁移方案及数据验证，再由 Owner 决定发行身份。保持包名，不擅自卸载、清数据或降低版本。

## 正式签名配置方案（尚未接入）

由 Owner 提供仓库外的 keystore 路径、别名和安全凭据注入方式，先校验证书摘要及旧版本相容性，再将 release signingConfig 接到专用配置。缺少任一正式参数时，正式候选构建应明确失败；本轮保留现有 debug 签名供本地测试。密码不得写入源码、Gradle命令行或日志；不输出私钥。发布版本码、正式身份和分发由 Owner 另行决定。

## 已查 Widget 架构与后续风险

Receiver 和数据 Provider 都不导出；FileProvider 仅开放自建 shared_images 缓存目录。Widget 通过 AppState→MethodChannel→私有 SharedPreferences→refreshAll 更新，系统周期为30分钟。一个 provider 按宽度选小/中布局，不是两个列表条目；当前点击通过广播记录本机事件并打开 MainActivity。小米桌面兼容性须实测，不能凭静态代码宣布通过。

P5 历史观察：当时快照未携带业务日期，跨日“今天”字段可能陈旧；当时仍使用 Flutter 默认位图，缺少 adaptive/round 资源。P6-A 已在代码及候选包中修复：快照增加业务日期与 UTC 偏移，过期提示打开 App 更新；图标替换为橘猫餐盘并补齐 adaptive/round 资源。真机跨日显示与桌面图标验证仍为 not_run，不据此宣称真机验收通过。
