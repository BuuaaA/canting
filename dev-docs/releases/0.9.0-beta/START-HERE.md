# 餐盘 0.9.0-beta 第一次测试

这是用户已授权发布的 beta 测试包，非 V1 正式封版；真机验证仍为 not_run，可交 Owner 执行测试。宠物美术保持现状，新图标为橘猫与餐盘。

1. 先记录手机型号、系统版本、是否已有餐盘。已确认 arm64-v8a 时选 arm64 主包；不确定时可选 universal 备用包（仍需核对支持的 ABI）。
2. 如果手机已有重要记录：先暂停覆盖升级。当前只有 JSON 导出，没有经验证的完整导入/恢复入口，系统自动备份也被禁用；复制导出文本不能当作完整可恢复备份。由开发协助在授权测试环境验证备份与恢复后再继续。不卸载、不清数据、不使用强制降级。
3. 空白设备或明确无须保留数据的测试设备，可将选定 APK 传到手机后点开，按系统提示允许该来源安装。不要同时安装两个包。安装错误时保留提示并反馈。
4. 查看桌面及系统应用信息的橘猫餐盘图标。若仍是旧图标，先记录截图，尝试等待桌面刷新或重启手机；不要清除应用数据或卸载排查。
5. 用一张获准使用的脱敏订单截图：分享→识别→确认→保存→历史查看。不要上传含姓名、地址或电话的截图反馈。
6. 纠正一个商品，结束进程重开，识别相同商品，检查是否复用纠正。飞行模式重复识别；首次离线和无 GMS 另行验证。
7. 添加餐盘伙伴 Widget，保存、编辑、删除记录，检查组件是否更新。未知项应显示“记录不完整”，无记录与已知零值不同。
8. 次日观察：组件旧布局保留明确记录日期；系统刷新发现过期后显示“打开餐盘更新今日记录”，旧数值隐藏。打开 App 后重算。系统30分钟更新请求不保证午夜准时执行，小米省电策略可能继续延迟。
9. 验证缩放、点击、结束进程和重启。按 feedback-template.md 反馈即可，工程日志和数据摘要由开发协助采集。

第一轮预计20–30分钟，不包括跨日等待。完整验收仍须执行 p5-device-checklist.md 中 B01–B09、C01–C04、D01–D02，并补真实图片、独立留出和危险场景证据。
