依赖关系与关键路径

关键路径：P0 冻结 → 爬虫结束 → P1 数据验收 → P2 本地语义 → P3 安全推荐 → P4 真实识别 → P5 真机发布 → P6 封版。

依赖类型处理
Nutradata 爬虫完成外部/数据未完成时只准备管线和 fixture，不消费增量文件
未提交共享文件资源冲突先 P0 归属审计，禁止多个 Agent 重叠写入
小米真机设备P5 必须由用户配合验证，模拟器不能替代

产能模型

角色职责可用产能假设护栏
产品 Owner最终决策、真机操作关键节点参与每阶段只需一次验收决策
Codex 产品经理范围、Prompt、验收阶段间审查不直接扩大开发范围
Trae/CodeBuddy实现、测试、交接约 8–13 开发日一次只执行一个阶段

风险矩阵

风险概率影响等级缓解/预案
原始数据可访问但不可再分发中高高raw 留仓库外；许可未确认时只发布自有派生标签和人工集
低置信度匹配被自动接受高高高集中阈值；中低置信度确认；未知绝不记零
多 Agent 覆盖未提交改动中高高P0 冻结；文件归属；阶段串行交接
模拟器通过但小米失败中高高内置 OCR 暂不替换；真机矩阵覆盖 Widget/分享/升级

缓冲策略

确定性需求 70%风险缓冲 20%弹性 10%

弹性项只包含文案微调和低风险体验改进。AI、社区和 iOS 不得占用 V1 缓冲。
